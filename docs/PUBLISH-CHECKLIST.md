# ПУБЛИКАЦИЯ АКТЁРА: ЧЕК-ЛИСТ И ГРАБЛИ

Правило оператора, 05.11.2026: **весь опыт публикации и все грабли должны быть
задокументированы, а новый актёр сверен по ним ДО публикации.**
Это критично, а не пожелание.

Проверка машинная, не «по памяти»:

```
python scripts/preflight.py                 # все актёры
python scripts/preflight.py vat-validator   # один
```

Exit code 0 = ни одного FAIL. Публиковать можно только при нуле FAIL.
Скрипт смотрит то же, что перечислено ниже: L1-L9 локально, P1-P9 на платформе.

---

## 0. Порядок, который не меняется

1. Боль пользователей лидера (правило №1).
2. Ниша по цифрам: оплачиваемые места, а не «сколько всего актёров».
3. Имя = поисковый запрос (правило №3).
4. Код: закрыть 1-2 боли по умолчанию, а не опцией.
5. Полигон и тесты В ПАПКЕ актёра, до всяких ворот.
6. `preflight.py` - ноль FAIL.
7. Манифест по БАЙТАМ (`scripts/manifest.py`).
8. Ворота Ореста: один запрос, один отчёт, одна правка (правило №2).
9. `apify push` только из папки актёра.
10. Пять полей карточки через API (раздел 3).
11. Публикация.
12. Замер позиции по запросам через сутки.

У опубликованного актёра **push и есть публикация**: новая удачная сборка сама
становится latest. Поэтому шаги 6-8 идут ДО пуша, а не после.

## 1. Имя и поиск

- `seoTitle` - максимум **60** знаков, `seoDescription` - максимум **200**. Длиннее
  даёт 400, и поле остаётся прежним.
- Название начинается с фразы, которую набирают в сторе. Своя формулировка идеи в
  начале названия = актёра не находят.
- Поиск стора **нечёткий**: на «email verifier» первым выходит LinkedIn-скрапер, на
  «pdf to text» - меню ресторана. Верх списка не брать без проверки названия и
  описания на релевантность.
- Замер: `GET /v2/store?search=<фраза>&limit=100`, искать себя по `name`. Если нас
  нет в первых 100 - менять название, а не ждать.
- В тесных запросах (700-900 актёров) решает популярность, а не текст: наш заголовок
  слово в слово, а в сотне нас нет. Вход - длинный хвост, оттуда вверх.
- Цифры и текущие позиции: `docs/SEARCH-TARGETS.md`.

## 2. Локальные грабли: что уезжает на платформу

| # | грабля | как проверяем |
|---|---|---|
| L1 | `.bak`, `.pyc`, `__pycache__`, логи уезжают как исходники | список файлов папки |
| L2 | нет обязательного файла (`.actor/actor.json`, `Dockerfile`, `src/main.py`) | структура |
| L3 | кириллица в коде и комментариях | скан всех текстовых файлов |
| L4 | длинное (U+2014) и среднее (U+2013) тире | скан, замена на дефис |
| L5 | нет тестов | `tests/*.py` |
| L6 | зависимости не закреплены | `==` в requirements |
| L7 | нет ignore-файла, тесты уедут | `.actorignore` |
| L8 | категории не в `actor.json`, только в API | расхождение с витриной |
| L9 | `defaultMemoryMbytes` не задан или 4096 | число в `actor.json` |

Отдельно, опытом:

- **`.apifyignore` CLI 1.11 НЕ читает.** Читает `.gitignore` в папке актёра и
  РОДИТЕЛЬСКИЙ `.gitignore`. Когда в корневой был `actors/`, пуши из папки актёра
  молча собирали версию из 4 файлов без кода. Когда правил не было, пуш из корня
  утащил `docs/`, `data/store_top.json` (464 КБ) и код двух других актёров.
  Правило: **пушить только из папки актёра**, после пуша тянуть `sourceFiles` и
  сверять список.
- **`.actorignore` в папке актёра работает**: тесты и `.pyc` на платформу не едут.
  Проверять фактом (`sourceFiles`), а не наличием файла.
- **Секреты только через env**, и проверять, что env реально доехал до контейнера.
  У нас env-переменная создалась с хешем значения, но в контейнер не пришла
  (`paths=1`), и актёр работал на константе в коде. Константа в коде = пароль на
  платформе: ротировать сразу.
- **Версии закреплять только те, что видел в живом прогоне.** Пин «по памяти»
  (`apify<3.0.0`) снёс SDK на 2.x и уронил сборку на импорте. Актёр пишет строку
  `deps: apify=... crawlee=...` в лог - оттуда и брать.
- **Кириллицу в регулярках писать `\u`-эскейпами**, иначе скан исходников ругается
  справедливо.

## 3. Пять полей карточки, которые push НЕ привозит

`apify push` везёт код и README. Карточка живёт отдельно.

| поле | что будет, если пусто | норма |
|---|---|---|
| `seoTitle` | в поиске нет ключа | заполнено, <= 60 |
| `seoDescription` | некликабельная карточка | заполнено, <= 200 |
| `categories` | актёр не в разделах стора | не пусто |
| `exampleRunInput` | кнопка Run и автотест падают | настоящий вход, без `helloWorld` |
| `defaultRunOptions.memoryMbytes` | 4096 МБ вместо 512 = переплата в 8 раз | по замеру пика |

Порядок: править **через API до публикации**, потом читать обратно.

Грабли поля:
- платформенный дефолт `{"helloWorld": 123}` стоял у четырёх актёров - кнопка Run
  и ежедневный автотест площадки падали бы;
- **Save в консоли перезаписывает `categories`** тем, что стоит в форме: после
  консольных правок категории перечитать и вернуть через API;
- `pictureUrl` у **приватного** актёра отсутствует вовсе - «иконки нет» по API у
  неопубликованного говорить нельзя, смотреть в консоли (картинка 512 px);
- загрузка иконки API не принимает (отвечает `invalid-picture-url`), только
  консоль: Publishing -> Display information -> Upload new image -> Save;
- «You have unsaved changes from last time» = превью в форме, а не сохранённый
  результат. Судить только по `pictureUrl` после Save и перезагрузки;
- `title` в `actor.json` и `title` на платформе расходятся: push обновляет не всё.

## 4. Деньги

- Модель **pay-per-event**: платформа считает события, вычисления покупателю
  бесплатны. Инвариант: **списано = доставлено**. Если строка оплачена и не отдана -
  это дырка, а не мелочь.
- В SDK 4.2.0 `ChargeResult.event_charge_limit_reached = True` значит «это событие
  УЖЕ списано, больше не влезет». Порядок: `charge` -> если `charged_count > 0`,
  отдать строку -> и только потом стоп. У нас было наоборот: 16 списаний при 15
  строках.
- Повтор `charge` с тем же `idempotency_key` внутри 3 минут отвечает 0, и это
  **не отличить** от исчерпанного бюджета. Поэтому: если первый вызов бросил, а
  повтор ответил 0 - строку всё равно отдать и встать с `charge-uncertain`.
- Минимальный потолок прогона у платформы - **$0.02**. Потолок ставит покупатель,
  наш рычаг только `minimalMaxTotalChargeUsd`.
- `chargedEventCounts` после SUCCEEDED показывает 0 и обновляется **20-35 секунд**.
  Не докладывать «списаний ноль» по свежему прогону.
- Комиссия площадки 20%. Маржа = цена минус комиссия; вычисления платит покупатель
  в своём аккаунте, это не наша маржа.
- Кэш-строки: если обещали «кэш бесплатен» - не списывать. Если списываем - прямая
  оговорка в разделе Price, а не только в абзаце.
- Мастер обещает «цена вступит через 14 дней», фактически `pricingInfo.startedAt`
  ставится в день включения. Верить `startedAt`.
- Правка цены **снова рассылает уведомление и перезапускает срок** - из-за долей
  цента не трогать.
- `defaultRunOptions` в консоли и запуск из CLI идут с разной памятью: CLI передаёт
  свою, кнопка Run берёт дефолт. Сверять оба.

## 5. Ворота и манифест

- Один круг = один запрос + один отчёт + одна правка. Порциями находки не
  принимаются (правило №2).
- Вердикт живёт **ровно для тех sha256**, что ревьюер видел. Любая правка после
  отчёта (даже строчка в README) его аннулирует.
- Манифест считается **по байтам** (`open(path,'rb')`). Хеш от декодированного
  текста с CRLF->LF даёт другой TOTAL и создаёт ложное «всё сошлось».
- Копия исходников и манифест кладутся в `docs/manifests/<актёр>/<версия>/`:
  исторический исходник из CLI не достать, сверять иначе нечего.
- Класс риска: где нет разбора чужих данных (IBAN, VAT, SSL, uptime, битые ссылки) -
  полигон + чтение кода + один живой прогон. Полный гейт - где решаем, что считать
  чужими данными и за что списывать.

## 6. После публикации

- Потолок платформы: **5 публикаций новых актёров за 24 часа** на аккаунт.
  Дословно: «You've reached the daily limit of 5 Actor publications. Try again in
  24 hours». Окно скользящее от первой публикации, не календарные сутки.
  Сборка и заливка (`push`) лимит не тратят - готовить можно сколько успеем.
- Аналитика: `Paying users` = 0 означает `Profit $0.00`; прогоны на free-плане
  выручки не дают. Наши собственные прогоны не считаются ни доходом, ни расходом.
- Payouts появляется только после первой публикации. `Billing details` (адрес,
  карта) - оплата наших расходов; `Beneficiary details` (PayPal) - куда приходят
  выплаты. Это разные формы, я их путала.
- KYC по паспорту - до первой выплаты. Минимум: $20 PayPal/Wise, $100 банк.
- Задержка индекса: иконка и название в поиске стора обновляются не мгновенно,
  страница актёра - сразу. «В поиске пусто» != «не встало».
