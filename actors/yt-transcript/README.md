# YouTube Transcript API: Bulk Captions, Fast

**The most-installed YouTube transcript Actor in the Store sits at 3.7★ out of 5 on 49 reviews, and the
complaints repeat: "no data returned", "no response for this video".** That is what silence costs a
rating. This Actor never goes silent.

Every link you send becomes a row. Either the transcript - plain text, timestamped segments, ready
SRT and VTT, language, human-or-auto flag, video metadata - or a row with `status: FAILED` and a
machine-readable reason: `NO_CAPTIONS`, `LOGIN_REQUIRED`, `EMPTY_TRANSCRIPT`, `VIDEO_NOT_FOUND`,
`LIVE_STREAM`. You always know which video failed and why, instead of wondering which ones vanished.

## The pain this removes

| The usual story | What happens here |
|---|---|
| A video without captions simply disappears from the output | It comes back as a row with a reason and is **not charged** |
| "Sign in to confirm you're not a bot" - YouTube blocks data-centre IPs | The Actor retries through a clean egress path by itself. You are not told to go and buy residential proxies |
| One run per video, so 100 videos = 100 runs | Paste up to 1000 links; eight are fetched in parallel |
| Transcript as a wall of text, subtitles left to you | `transcript`, `segments`, `srt`, `vtt` in the same row |
| You pay for the attempt, not the result | The charge fires **after** the transcript is stored |
| Language guessed silently | Ask for `en`, get `en`, or the original track - and `availableLanguages` tells you what exists |

## What you get per video

| Field | Meaning |
|---|---|
| `transcript` | the whole speech as one plain-text string |
| `segments` | every cue with `start` (seconds), `duration`, `text` |
| `srt`, `vtt` | subtitles ready to save and play |
| `language`, `availableLanguages` | which track was used and which ones exist |
| `isAutoGenerated` | true = YouTube speech recognition, false = human captions |
| `videoTitle`, `channel`, `durationSeconds`, `viewCount` | video metadata |
| `status`, `error`, `reason` | SUCCEEDED/FAILED and, when failed, exactly why |

## Who uses it

- **Content teams** - turn a channel's back catalogue into searchable text.
- **Research and journalism** - quote a video with timestamps, not with a memory of what was said.
- **SEO and repurposing** - transcript to blog post, subtitle files for re-uploads.
- **AI and RAG pipelines** - feed an assistant with what people actually said, as clean text.
- **Compliance and moderation** - keep a text record of published videos.

## Input

```json
{
  "videoUrls": [
    "https://www.youtube.com/watch?v=dQw4w9WgXcQ",
    "https://youtu.be/jNQXAC9IVRw",
    "https://www.youtube.com/shorts/kJQP7kiw5Fk",
    "kJQP7kiw5Fk"
  ],
  "language": "en",
  "preferManualCaptions": true,
  "includeSegments": true
}
```

All URL shapes are accepted: `watch?v=`, `youtu.be/`, `/shorts/`, `/embed/`, `/live/`, or a bare
11-character video ID.

## Use it from code

```bash
curl -X POST "https://api.apify.com/v2/acts/YOUR_USER~youtube-transcript-api-fast/run-sync-get-dataset-items?token=YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"videoUrls":["https://youtu.be/jNQXAC9IVRw"]}'
```

Works as an MCP tool from Claude, Cursor and ChatGPT as well - the input is a plain list of links.

## How the requests travel (in plain words)

YouTube rate-limits data-centre addresses, so when the direct path is refused the Actor retries
through its own egress path and falls back to a direct connection otherwise. Your own proxy can be
plugged in through `proxyConfiguration` and then takes priority. Nothing about your run is stored on
that path - only the request for the video you asked for passes through it.

## Cache

A transcript that was fetched once is kept in the storage of the account that ran the Actor for 12 hours
(`cacheMinutes`). Ask for the same video again inside that window and it comes back instantly, marked
`fromCache: true` - and YouTube receives no second request for it. That last part is not a micro-saving:
repeated identical traffic is what gets an address rate-limited in the first place.

## Limits worth knowing

- Captions must exist on YouTube's side. A video whose uploader disabled them cannot be transcribed
  here - that is reported as `NO_CAPTIONS`, not as a charge.
- Age-restricted videos answer `LOGIN_REQUIRED`; we do not sign in with an account.
- Live streams in progress have no captions yet.

## Feedback

Found a video that fails although it clearly has captions? Open an issue on the Actor page with the
link - that is the fastest way to get it fixed.

## Cache and billing

A cached transcript is still a delivered transcript, so a row served from the cache is charged
like any other row. The cache saves wall-clock time and spares YouTube a repeated request for the
same video - it is not a discount.
